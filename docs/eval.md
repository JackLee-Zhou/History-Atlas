## 如何执行（用户本机，有 key 时）

1. 启动应用，进入“设置”，填写自己的 `Base URL`、模型名、`API Key`，点“测试连接”；非 key 选项自动保存，Key 填好后点“保存 Key”。
2. 选一组评估段落（建议 8 段）：赤壁、官渡、长平、淝水、土木堡、安史之乱、楚汉、靖难。
3. 每段记录：
   - 是否返回合法结果（schema / 页面是否报错）；
   - 识别出的地点集合，与人工标注的“应出现地名”对比，算召回；
   - 已定位地点逐一人工抽检今地是否正确，算已定位正确率；
   - 未定位/待考是否合理；
   - 选段耗时（浏览器 Network 面板）；
   - token 用量（如 provider 返回 usage）。
4. 把结果写进本文件下方表格；**不要把明文 key、原始书稿全文或 `.data` 内容贴进来**。

## 已知评估风险

- 模型可能把“后出小说地名”当成史实地名（如三江口、南屏山）；界面应保留待考/低置信。
- 古地名存在同名异地（江陵/荆州、南阳、新城）；当前策略是多候选待考，不静默选。
- 模型可能引用相距很远的句子作为证据；服务端只保证 quote 逐字存在，不保证语义充分，需要人工抽检。
- 章节模式多窗口合并可能重复/漂移；建议先以选段模式验收。
